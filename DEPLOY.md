## Установка в Supabase

### 1. Применить schema.sql

1. Открыть Supabase Dashboard → SQL Editor
2. Скопировать содержимое `schema.sql`
3. Нажать «Run»

> **Важно:** Если проект уже создан, новые таблицы `expenses` и `project_changes` добавятся автоматически. Существующие данные не пострадают.

### 2. Обновить файлы на сервере

Заменить 4 файла на хостинге:

| Файл | Что изменилось |
|------|---------------|
| `schema.sql` | +tables expenses, project_changes, RPC delete_project/add_expense/log_project_change, trigger, RLS policies |
| `app.js` | +статус «В производстве», +загрузка expenses/changes, +UI маржи/расходов/истории, +addExpense, +exportWoodToPDF, +поиск |
| `styles.css` | +margin-display, +expense-row, +change-row, +searchBar |
| `index.html` | +searchBar для объектов, +кнопка PDF для дерева |

## Ручная проверка (чеклист)

### ✅ Удаление проекта
- [ ] Открыть карточку объекта
- [ ] Нажать «Удалить объект»
- [ ] Подтвердить → объект удалён вместе с задачами, оплатами, деревом

### ✅ Расходы и маржа
- [ ] Открыть карточку объекта
- [ ] Нажать «+ Расход»
- [ ] Ввести сумму, выбрать категорию → Сохранить
- [ ] В разделе «💰 Фактическая маржа» увидеть: Доход − Расходы = Маржа
- [ ] Если маржа отрицательная — блок красный

### ✅ История изменений
- [ ] Изменить название объекта, сумму, статус, предмет договора
- [ ] В карточке ниже появится секция «📝 История изменений»
- [ ] Каждая запись: поле, старое значение → новое значение, кто, когда

### ✅ Статус «В производстве»
- [ ] В карточке объекта в статусе выбрать «В производстве»
- [ ] Статус сохраняется

### ✅ Экспорт дерева в PDF
- [ ] Открыть вкладку «Дерево»
- [ ] Нажать «📄 PDF»
- [ ] Открывается новая вкладка с таблицей заказа дерева
- [ ] Кнопка «Печать / Сохранить PDF»

### ✅ Поиск по объектам
- [ ] Ввести текст в поле поиска
- [ ] Фильтрует по названию, заказчику, предмету договора

### ✅ Валидация файлов
- [ ] В карточке объекта нажать «+ Файл»
- [ ] Выбрать .jpg, .png, .pdf, .doc, .docx, .xls, .xlsx → OK
- [ ] Выбрать .exe → не допускается

## Предостережения

1. **RLS-политики:** Новые таблицы используют ту же логику `is_member(wid)` что и существующие. Если в проекте уже есть данные с другой структурой workspace — проверить права доступа.

2. **Триггер `project_changes_trigger`:** Записывает изменения в ключевые поля (name, amount, status, items, due_date, contractor). Не записывает изменения в progress, startDate, closingReceived, needs_wood — по решению можно добавить.

3. **Миграция данных:** Существующие платежи не удаляются. Существующие проекты не затрагиваются. Все изменения обратимы — можно удалить новые таблицы и вернуться к старой схеме.
